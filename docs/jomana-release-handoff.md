# Jomana’s mobile and deployment handoff

Mohamed owns backend APIs, security, tests and the separate administrator console. Jomana owns Expo integration, hosting, staging, production deployment and store builds. No consumer web application is required. Record the exact backend SHA and mobile build ID for each acceptance run.

| V2 sign-in and session recovery | [Session contracts](auth-sessions.md). Single-flight refresh, persist retry key and refresh credential together in SecureStore, honor bounded recovery, clear credentials on logout. | Cold restart, lost response, revocation and multi-device tests. |

| Recovery, monitoring and rollout | [Backup and restore](backup-and-restore.md), [alerts](monitoring-and-alerting.md), [smoke tests](production-smoke-tests.md) and [launch checklist](LAUNCH_CHECKLIST.md). | Timed isolated restore, deletion reconciliation, exercised alert escalation, rollback decision and owner sign-off. |

Keep development local until shared HTTPS is needed. Use a temporary CX23 for online testing, then persistent CX23 staging only when needed. Consider a separate CX33 production host after capacity, restore and operational acceptance. Managed PostgreSQL remains the higher-reliability alternative. Record approved budget, region and recovery objectives before ordering anything.

Use independent secrets, databases, Redis state, push projects and permissions per environment. Follow the configuration inventory for exact variable names and key formats. Exchange real values through the assigned secret manager. Before store submission, verify the public privacy policy, functioning external deletion channel, backup retention, Expo credentials and real-device behavior. Record store and production approvals separately from backend test evidence.

## Restricted administrator origin

Run the BFF as a separate unprivileged process with only ADMIN_ORIGIN (exact public HTTPS origin) and API_ORIGIN (fixed internal upstream). Browser requests reach it through a dedicated access-restricted Caddy hostname. Preserve the original Host and the BFF's same-origin referrer policy for form submission. The sample mobile API hostname has its own header policy. Deny direct public access to /admin on the mobile origin while leaving its mobile routes available. Enforce ingress limits: an anonymous form reserves one of 128 slots. Operate one BFF process/replica; a crash invalidates local handles and may require upstream device-session revocation. Use a managed operator device. Do not record form data, query strings, MFA headers or browser cookies. Grant self-approval needs offline audit review and operational alerts.
